# 手机速查库设计

## 目标

把散落在不同项目中的非敏感 HTML 复制到一个专用发布库，通过 GitHub Pages 提供一个 iPhone 友好的统一首页，并为每份内容保留稳定的独立链接。

## 已确认原则

- 原始 HTML 保留在原项目中，速查库只保存发布副本。
- 同一主题更新时覆盖现行版本，永久链接不变；历史版本由 Git 保存，不在首页堆积。
- 首页采用“分类入口”布局：顶部搜索、中部分类、下部最近更新。
- 分类由 Codex 沿用已有分类，必要时新增，不要求 Eric 手工填写表单。
- 优先接收单文件 HTML；存在本地依赖时复制依赖并检查引用。
- 尽量不依赖外部 CDN。
- 只有在 Eric 明确说“发布到手机速查”或同等指令时，才复制、提交并推送。

## 架构

静态站点使用原生 HTML、CSS 和 JavaScript，不引入框架、数据库或构建服务。`index.html` 读取 `content.json` 生成搜索、分类和最近更新区域；每份内容位于 `pages/<slug>/index.html`，因此更新正文不会改变链接。

`scripts/publish.mjs` 接收源 HTML 路径及可选标题、分类和 slug。它复制 HTML 及相对本地依赖，拒绝逃出源目录的路径，更新 `content.json`，然后由独立发布命令完成 Git 提交和推送。复制与推送分离，便于发布前本地验证，也避免未明确授权时自动对外发布。

## 文件职责

- `index.html`：移动端首页外壳。
- `assets/site.css`：首页视觉样式和 iPhone 安全区适配。
- `assets/site.js`：加载目录、搜索、分类切换和最近更新。
- `content.json`：唯一内容目录，记录标题、分类、slug、更新时间和路径。
- `pages/<slug>/index.html`：发布后的速查正文。
- `scripts/publish.mjs`：复制正文与依赖、更新目录。
- `scripts/check.mjs`：检查目录结构、重复 slug、缺失文件与本地引用。
- `tests/`：发布工具和目录检查的自动测试。
- `README.md`：只记录 Eric 与 Codex 需要的日常发布用法。

## 发布数据流

1. Eric 指定某个原始 HTML，并明确要求发布到手机速查。
2. Codex运行发布工具；新主题生成稳定 slug，已有主题沿用原 slug。
3. 工具复制页面与依赖并更新 `content.json`。
4. 自动检查首页目录、目标文件及相对资源引用。
5. Codex 本地预览并提交、推送到 GitHub。
6. GitHub Pages 更新固定主页；iPhone 刷新主屏幕入口即可看到新内容。

## 内容规则

- `slug` 一经发布不因标题变化而自动修改。
- 更新识别优先使用明确 slug，其次使用目录中完全相同的标题。
- 分类不存在时可以新增；空分类统一归入“其他”。
- 最近更新按 ISO 8601 时间倒序显示。
- 删除内容不是发布工具的默认能力，需单独明确指令。
- 首页和正文不得写入访问令牌、电脑绝对路径或其他本地信息。

## 异常处理

- 源文件不存在、不是 HTML、slug 冲突或本地资源缺失时，停止发布并说明具体文件。
- 外部 HTTP/HTTPS 资源允许保留但给出警告，不宣称已实现离线可用。
- Git 推送失败时保留本地变更，不重复创建内容记录。
- GitHub Pages 尚未完成刷新时，以本地检查通过和远端提交存在为准，不虚报页面已上线。

## 验收

- iPhone 宽度下首页无横向滚动，可搜索并进入分类。
- 每份示例页面可通过稳定的 `/pages/<slug>/` 地址访问。
- 同 slug 再次发布时链接不变且目录只有一条记录。
- 缺失相对资源会让检查命令失败。
- 本地测试全部通过，GitHub Pages 首页和独立页面均可访问后才视为上线完成。
